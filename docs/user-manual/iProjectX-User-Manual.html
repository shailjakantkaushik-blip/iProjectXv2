Start here

Sign in, land on Home, know your role

Sign in

  1. Open the organisation URL (or www.iprojectx.com / www.iprojectx.com.au) and choose Sign in.
  2. Complete MFA (authenticator TOTP). MFA is required for every user.
  3. If your organisation uses SSO, you may be sent through SAML first. If the org uses an IP allowlist, you must be on an allowed network.
  4. First login may ask you to change a temporary password.

Home

After sign-in you land on Home in Command Center. Shortcuts follow your role. Executives see Pulse and Cockpit first. Admins see Team, Configuration, and Project data access. PMs see My Work, Projects, and Work Items. You only see projects your Project Access grant allows — including Home KPIs.

Roles

  • Org admin / Admin — users, roles, navigation, branding, delivery methods, resources, Data Editor, holidays.
  • BU lead / PM — plan projects, Estimation Planning, work items, RAID, gates, timesheet approval.
  • Executive — Pulse, Cockpit, dashboards, Financials. They steer; they do not rewrite Plan.
  • Platform admin — control plane across tenants (not a tenant PMO role).

My Work and the bell

My Work is your personal queue: assigned work items, timesheet approvals, decisions waiting on you, unread alerts.

The bell in the header is the same notifications. Over-allocation alerts (leave/holidays) land here for the person and their resource manager.

If a page is missing from the sidebar, it is either hidden in Navigation sequence or outside your role / Project Access. Ask an org admin — do not assume the feature is gone.

First week · org admin then PM

Stand the organisation up, then create the first project

Org admin — before anyone plans

1

Team & Roles

Invite users. Assign org admin, PM, executive, BU lead. Activate accounts. Link a resource record to each person who will timesheet.

2

Business Units

Structure BUs and programs so filters and access grants have somewhere to hang.

3

Resources

Name, role, location, hours/day, cost rate, resource manager. Location drives public holidays. Hours/day is the Over / Optimal / Under cap.

4

Holidays & leave

Resources → Holidays & leave. Geography holidays (location, or * for all). Dated leave (Annual / Sick / General). These weekdays drop out of capacity.

5

Delivery methods, navigation, access

Gate names. Sidebar order. Project data access so executives do not see a neighbour’s RAID.

PM — create and shape a project

  1. Programs → New Project (or the create wizard). Set Strategic Alignment, program, functional area, delivery method, owner, planned dates.
  2. Core stream is created. Add extra streams if the work has real lanes (data, security, change).
  3. Set Budget on the stream in Data Editor — that is the approved envelope. The project is the roll-up.
  4. Open the project workspace from Projects. Use the dropdown to switch projects.
Demand Pipeline is for ideas that are not projects yet. Convert when the organisation is ready — do not plan FTE on an idea.

Operating loop · Plan

Freeze a Plan — then keep Forecast honest

Project Estimation Planning

This is the estimate board. Select a role, drag a named person onto a stream phase (or click person then phase). Effort is hours / days / weeks. Working days already exclude weekends, location holidays, and that person’s leave.

If assigned hours exceed remaining capacity you get Save anyway? Confirming still saves, toast-warns you, and notifies the person’s linked login and resource manager.

Apply planned baseline writes Plan only: planned dates, CapEx/OpEx plan, Planned FTE. It does not write actuals. Forecast columns start equal to Plan when still empty.

FY Allocation

Split Budget and Forecast $ by financial year. Year totals must not exceed the stream envelope. Forecast can move if a phase slips; Budget and Plan stay put until someone formally changes them.

Write-path rules (do not mix)

Budget — Data Editor → Project Streams.
Plan — Estimation Planning → Apply.
Forecast — FY Allocation forecast $ (late gates can lift phase forecast).
Demand — work-item hours.
Actual — approved timesheets + posted other OpEx.

Financials, Budget vs Plan, Phase Financials, EVM, and Cost vs Benefit all read those layers. They are not a second place to type Budget.

Operating loop · Demand and Actuals

Hand out work, then book the hours that happened

Work items (Demand)

  1. Work Items → choose project and stream (Core is the default lane).
  2. Title, estimate hours, planned dates, assignees (search resources). Stage gate for Waterfall/Hybrid; Sprint for Agile/Hybrid.
  3. Load chips are Over / Optimal / Under vs each person’s hours/day. Optimal is ≥ 60% of the cap. Over is above the cap. A window that is fully leave/holidays is Over even if daily math looks quiet.
  4. Lane pending = allocated (Plan) − work-item demand. Use allocated as the ceiling when you set demand hours.

Work Board is the same items as a board. Timeline and Roadmap × Governance show dates against gates.

Timesheets (Actuals)

  1. Timesheets → pick the week. Rows appear for assigned work items (linked login on the resource).
  2. Enter hours Mon–Sun. Daily totals flag Over / Optimal / Under against hours/day.
  3. Submit. PM then Resource Manager approve. Only approved hours become Actual FTE $ (hours × rate).
  4. Resource setup (hours/day, rate, manager) is on Timesheets → Resource setup for people you may edit.

Resources utilisation

Resources shows allocation vs demand vs actual. Monthly capacity is working days × hours/day after holidays and leave — not a flat week × 4.33. Holidays & leave tab is where you maintain the calendar.

Operating loop · Steer

Gates, RAID, and decisions — with evidence

Stage gates

Open Stage Gates (or the project’s Streams / gates). Pass, hold, or reject with a checklist. The decision is stored — it does not live in email. A late gate can raise phase Forecast; it does not silently rewrite Budget or Plan.

Investment Committee

Portfolio-level go / hold / stop with financials on the same page. Use it when the ask is bigger than a stream gate.

RAID

Risks, Actions, Issues, Decisions — plus stakeholders and lessons. Filter by project, stream, forum, sponsor, gate. Critical and overdue items escalate. Record outcomes on Decisions; My Work shows items waiting on you.

Dependencies & CPM

Project-to-project (and work-item) links. Schedule CPM is the critical path. A delay what-if belongs in Executive Intelligence, not a side spreadsheet.

Health Engine — RAG is earned

Weighted score: Schedule 20%, Financial 20%, Delivery 15%, Scope 10%, Resource 10%, Risk 10%, Dependencies 10%, Benefits 5%. Bands: Green ≥ 80, Amber 65–79, Red < 65. A named override is allowed and marked M so nobody pretends the engine agreed. Dashboards that show overall RAG use the same engine unless overridden.

Executive pack (read, then decide)

Portfolio Pulse — six areas (financial, delivery, resources, risk, benefits, dependencies) and what changed this week. Executive Cockpit — attention cards, scoreboard, project summaries. Executive Dashboard — charts and register. Executive Intelligence — delay cascades and what-ifs. Executive Reports / Report Builder — packs you can take to the meeting.

Admin, data, trust

Keep the workspace true without becoming the bottleneck

Configuration

Team, BUs, holidays, stage gates, chart theme, billing, org settings, Data Editor. Org admins also get integrations (Jira into Demand), navigation sequence, page-download policy, project access, alert emails, closed-project purge.

Project data access

Limit a role or a user by Strategic Alignment, program, functional area, project, and stream. Grants apply to pages, KPIs, dropdowns, and Home — not only the project list.

Data Editor

Direct table edit plus Excel import/export. Use it for Budget on streams, holidays, leave, reference data. It is not a bypass for timesheet actuals.

Integrations

Jira can land demand in the pipeline. Webhooks follow the same tenancy rules. Azure DevOps and ServiceNow are not claimed as shipped connectors.

Trust controls you will be asked about

  • MFA — authenticator TOTP for every user.
  • Isolation — row-level security per organisation.
  • Optional SSO — SAML per organisation. Optional IP / CIDR allowlists.
  • Optional BYOD — tenant registers on your PostgREST-compatible database; auth stays on iProjectX.
  • In-house AI — default. External model only on request.
  • White-label — logo, colours, auth experience. Branding does not weaken tenancy.
  • Evidence — audit log, Excel evidence packs. Readiness for SOC 2 / ISO 27001 — not a certificate claim.

A typical week, recap

  1. Monday — Pulse / Cockpit: what moved, which red needs a decision.
  2. Tuesday — Estimation Planning or work items if the Plan or Demand changed.
  3. Wednesday — RAID and gates. Record the decision in the product.
  4. Thursday — timesheets in; approve what is true.
  5. Friday — Financials: Plan vs Actual vs Forecast. Do not “fix” Budget because a phase is late.
